# 股票研究 P0 修复设计

## 目标

修复两个阻断生产可用性的缺陷：主题请求不应触发候选股票联网搜索；生产数据必须能确定性地产生规则引擎消费的评分输入。

## 范围与非目标

- 覆盖 `StockAnalysisAgent` 的主题路由与单股/比较研究的评分输入构建。
- 保持 `ResearchPipeline`、`RuleEngine`、旧状态字段和 API 响应契约不变。
- 不修改主题发现、管理员审核、审计快照重放、数据新鲜度门禁或前端呈现；它们不属于本次 P0 范围。

## 设计

### 主题请求优先解析

`StockAnalysisAgent.invoke` 先用已有状态、槽位和消息调用 `parse_analysis_request`。当结果为 `theme_screening` 时，直接调用 `ThemeScreener`，不得调用 `search_candidates` 或任何候选股票发现接口。

仅对非主题的 `stock_recommendation` 请求，在解析出的股票代码为空时调用候选发现；随后以发现的代码重新解析请求，保证下游只消费统一的 `AnalysisRequest`。

### 原始数据到评分输入的转换

新增研究层的纯函数评分构建器，输入为单只证券的原始 `indicators` 与前复权 `history`，输出可选的 `fundamental_score`、`technical_score` 和 `risk_score`。它只使用显式字段别名，不访问网络、不调用模型、不保留调用状态。

- 基本面分数：基于可识别的 ROE、营收增长、净利润增长和 PE/PB 等字段；缺失部分指标时仅使用可验证的可用项，并记录限制；没有任何可识别指标时为缺失。
- 技术面分数：从至少 60 根前复权 K 线计算趋势、动量与波动度；数据不足时为缺失。
- 风险分数：从波动度、最大回撤以及可用的估值/财务风险信号计算；无法计算时为缺失。

转换器将评分和限制写入快照的 `indicators`，既有 `RuleEngine` 继续只负责版本化权重、风险门禁与行动结论。Provider 已显式提供同名评分时也不采信，避免外部数据源绕过仓库内规则。

## 错误处理

数据抓取或字段解析失败不抛出伪造评分；评分保持缺失，由现有规则引擎输出“数据不足”。主题请求中的筛选器异常仍沿用现有降级响应。

## 验收与测试

1. 主题请求在没有股票代码时不调用 `search_candidates`，并可完成内存主题筛选测试。
2. 原始、完整的财务和 K 线输入能产生三项评分，并被 `RuleEngine` 判定为可关注或观望，而不是因评分字段缺失降级。
3. 缺少原始指标或历史数据时不产生伪造评分，行动结论仍为“数据不足”。
4. 原有研究契约、流水线、主题筛选和图路由测试继续通过。
