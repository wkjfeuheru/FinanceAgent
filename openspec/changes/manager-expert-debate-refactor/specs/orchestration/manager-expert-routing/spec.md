## Purpose

定义"总管-专家"编排能力：总管负责识别意图、抽取独立需求描述、路由到对应专家并将专家结果汇总为最终回复；各专家在内部自行完成字段抽取、任务规划与执行，使调度逻辑可观测、可扩展、可回退。

## ADDED Requirements

### Requirement: 总管只做意图识别与独立需求描述抽取

总管（ManagerAgent）SHALL 在单一节点内完成意图识别与独立需求描述抽取：接收用户当前消息与上下文，先识别本轮全部意图，再为每个意图抽取一条独立的需求描述（对用户原始意图的忠实转述，不加工、不拆分执行细节）。意图识别 MUST NOT 作为独立步骤或独立 Agent 存在，总管也不直接执行任何金融数据工具，更不做子任务依赖、执行顺序或并行分组的规划。

#### Scenario: 多意图请求抽取为多条独立需求描述

- **WHEN** 用户发送包含"分析贵州茅台基本面，并为我配置资产组合"的消息
- **THEN** 总管在单一节点内识别出股票分析与资产配置两个意图，并为每个意图抽取一条独立需求描述（如"分析贵州茅台基本面"、"为我配置资产组合"），将两条需求分别映射到股票分析专家与资产配置专家，不做进一步的任务拆分加工

#### Scenario: 纯闲聊路由到闲聊专家

- **WHEN** 用户发送"今天天气怎么样"且总管判定为 casual_chat
- **THEN** 总管将需求路由到闲聊专家（CasualChatAgent），由闲聊专家生成闲聊回复，不调度任何数据获取、分析、资产配置或产品解读专家，也不产生独立的合规专家任务

### Requirement: 总管按需求描述路由到对应专家

总管 SHALL 通过 LangGraph 条件边将每个识别出的意图需求路由到对应专家 Agent，并将完整上下文（用户消息、需求描述）透传给该专家。系统 MUST NOT 单设独立的数据获取专家节点或画像专家节点；各专家 SHALL 在内部自行完成字段抽取、任务规划与执行，并通过 tool calling 自行获取所需数据。

#### Scenario: 股票分析专家自行规划并获取数据后分析

- **WHEN** 用户需求描述包含 fundamental_analysis 意图
- **THEN** 总管将完整上下文路由到股票分析专家，由该专家内部规划执行步骤，通过 tool calling 调用 `data/` 层数据源获取行情/财务/K 线数据后再分析，而非经过独立的数据获取专家节点

#### Scenario: 候选搜索由股票分析专家内部规划两阶段 tool calling 完成

- **WHEN** 用户需求描述包含 candidate_search 模式
- **THEN** 股票分析专家在内部规划"先搜索候选股票列表、再逐只获取基本面数据"的执行步骤，全程在该专家内部完成，不依赖总管的子任务规划

#### Scenario: 产品解读意图路由到产品解读专家

- **WHEN** 用户需求描述包含 product_analysis 意图（用户询问单只产品深度透视或产品对比）
- **THEN** 总管路由到产品解读专家，由其内部规划并查询产品库，生成深度透视或对比评估结果

### Requirement: 专家在内部自行完成字段抽取、任务规划与执行

系统 MUST NOT 设置独立的画像专家节点；各专业 Agent SHALL 在内部自行从用户消息中抽取自身所需字段（如股票分析专家抽取股票名称/代码、资产配置专家抽取风险偏好/投资金额/投资年限、产品解读专家抽取产品名称/代码），并自行完成"任务规划 -> 工具调用/数据获取 -> 执行 -> 产出结果"的完整闭环，不依赖总管提供子任务依赖、执行顺序或并行分组，也不依赖统一画像专家预抽取字段。

#### Scenario: 专家根据需求描述自主抽取字段并规划执行

- **WHEN** 股票分析专家收到"分析贵州茅台基本面"的需求描述与完整上下文
- **THEN** 该专家在内部自主抽取股票名称"贵州茅台"、识别其股票代码，自主规划需获取的行情、财务、K 线数据并依次调用工具，最终产出基本面分析结果，而非等待总管或画像专家下发预抽取的字段

### Requirement: 总管汇总专家结果为最终回复

系统 MUST NOT 设置独立的合规风控专家节点；总管 SHALL 在所有专家任务完成后，按用户友好的顺序合并各专家产出的结果片段，并自行合成面向用户的最终回复，最终回复 MUST 包含风险提示。

#### Scenario: 多专家结果合并并附加风险提示

- **WHEN** 股票分析专家与资产配置专家均产出结果
- **THEN** 总管将两者合并为同时包含"行情与分析"与"资产配置"章节的回复，并在结尾附加风险提示，全程不经过独立的合规专家节点

### Requirement: 专家失败时总管执行回退

当某个专家因超时、数据源不可用或推理步数超限而失败时，总管 SHALL 标记该专家对应的需求为降级状态，并基于已有结果生成可交付的回复，而非整体中断工作流。

#### Scenario: 专家内数据获取失败时降级为提示语

- **WHEN** 股票分析专家在 tool calling 获取某只股票数据时因网络异常失败
- **THEN** 总管将该需求标记为降级，在最终回复中对该股票输出"暂无可用数据"提示语，同时正常输出其他成功专家的结果

### Requirement: 总管路由保持现有编排约束

总管-专家编排 MUST 保留现有架构约束：LangGraph StateGraph + SqliteSaver checkpoint、各专业 Agent 独立上下文（通过 `AdvisorState` 显式传递数据）、DeepSeek 作为唯一 LLM 提供方、SSE 流式接口与进度回调。

#### Scenario: 对话跨轮通过 checkpoint 恢复

- **WHEN** 用户在第二轮对话中补充"预算 50 万"
- **THEN** 系统通过 SqliteSaver checkpoint 恢复第一轮的 `AdvisorState`（含已识别的股票与画像），总管基于恢复的状态继续意图识别与路由
