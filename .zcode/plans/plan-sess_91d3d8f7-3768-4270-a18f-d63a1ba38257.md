## 目标
1. 把两个管理员功能（待审核线索、主题注册表）从用户页移出，改为**仅管理员可见的独立「管理」入口**。
2. 为对话增加**侧边栏内联的新建 + 列表 + 删除**，并加固**会话隔离**（归属校验 + Redis 键按 customer 隔离）。

## Part 1 — 管理员入口与用户页分离

**后端：下发 is_admin**
- `finance_agent/api/routes.py`：新增 `_is_admin(customer_id) -> bool`（`customer_id.upper() in ADMIN_CUSTOMER_IDS`）。

- `GET /api/me`（routes.py:111-124）：返回字典补 `is_admin`。
- `finance_agent/api/schemas.py`：`UserInfo` / `LoginResponse` 增 `is_admin: bool = False`。

**前端：独立管理抽屉**
- `frontend/src/types/index.ts`：`UserInfo` / `LoginResponse` 增 `is_admin?: boolean`。
- `frontend/src/components/LoginView.vue:77-84`：登录时把 `res.is_admin` 写入 `UserInfo`。
- `frontend/src/App.vue`：
  - 新增 `isAdmin` computed（`currentUser.value?.is_admin === true`）与 `adminOpen` ref。
  - 顶栏 `.header-right` 增一个 `v-if="isAdmin"` 的「管理」按钮（仅管理员可见）。
  - 新增 `<el-drawer v-model="adminOpen">`，内部用 `v-if="adminOpen"` 包裹 `ThemeReviewQueue` + `ThemeRegistryPanel`（非管理员：按钮不存在 → 抽屉不打开 → 组件永不挂载 → **零管理员请求**）。
  - **移除**侧边栏用户区的 `ThemeReviewQueue` / `ThemeRegistryPanel`（App.vue:187-188）。
  - `onMounted` 增 `refreshIdentity()`：调用已有但未使用的 `getCurrentUser()`，把返回的 `is_admin` 合并进 `currentUser`（保留本地 token），失败则回退本地存储。解决「已登录用户 localStorage 里没有 is_admin」的陈旧态。
- `ThemeReviewQueue.vue` / `ThemeRegistryPanel.vue`：保留现有 403 静默兜底作为防御，但它们只在管理抽屉内挂载。

## Part 3 — 会话隔离加固

**A. 路由归属校验（`finance_agent/api/routes.py`）**
- `DELETE /api/conversations/{customer_id}/{conversation_id}`（423-430）：删除前先用 `get_database().get_conversation(conversation_id, customer_id)` 校验归属，非本人 → 404「对话不存在」；再删除。
- `POST /api/chat`（146-170）与 `POST /api/chat/stream`（173-203）：当 `conversation_id` 非空时，校验其归属，非本人 → 404，杜绝写入他人会话。空 id（新建）不校验。

**B. 删除结果与记忆清理（`orchestrator.py` `delete_checkpoint_conversation` 496-504）**
- 采纳 `get_database().delete_conversation(...)` 的返回值；仅当确实删除了本人的行时才 `run_state.delete(...)` 与 `memory.store.clear_conversation(...)`，并据此返回 `True/False`（使路由 404 分支真正生效）。

**C. Redis 记忆键按 customer 隔离（`finance_agent/orchestrator/memory.py`）**
- 键格式：`finance_cs:conv:{customer_id}:{conversation_id}:window` 与 `:summary`（`_window_key` / `_summary_key` 增 `customer_id`）。
- `RedisMemoryStore` 五个方法增 `customer_id`：`append_window_message`、`get_window_messages`、`get_summary`、`set_summary`、`clear_conversation`。
- `AgentMemoryContext`：`append_window_message` 增 `customer_id`；`update_recent_summary` 增 `customer_id`（当前无调用方，仍保持接口一致）；`load_context` 已有 `customer_id`，透传给 store 调用（230/232）。
- 调用方全部已有 `customer_id` 在作用域：`orchestrator._persist`（423-424）、`delete_checkpoint_conversation`、`reset_session`（522）；`routes.clear_records`（479-480）、`delete_account`（525）改用带 `customer_id` 的 `clear_conversation`。
- **兼容性**：旧键 `finance_cs:conv:{conversation_id}:*` 不会被读取（记忆本就 TTL 最短 1 小时、best-effort），属可接受的一次性丢弃；`clear_records` 的 `finance_cs:*` 扫描仍能清理残留键。计划在 README 记录该变更。
