# orchestrator 目录重构:平铺模块归入功能子包

## 目标结构(方案 A)

```
finance_agent/orchestrator/
├── __init__.py              # 包门面(仅改无,memory 仍在根目录)
├── orchestrator.py          # AdvisorSystem 门面 —— 不挪,内容只改 import
├── contracts.py             # 全包契约中枢(~50 处引用)—— 不挪
├── compliance.py            # 统一合规出口 —— 不挪(自成一体的子系统)
├── memory.py                # 记忆系统 —— 不挪(避免 __init__ 层变动)
├── graphs/                  # LangGraph 宿主图组装(只组装,节点在 nodes/)
│   ├── supervisor_graph.py      ← supervisor_graph.py
│   ├── plan_execute_graph.py    ← plan_execute.py(补 _graph 后缀,与 nodes/plan_execute.py 区分)
│   └── conversation_graph.py    ← conversation_graph.py
├── routing/                 # 意图理解与参数补全(HITL)
│   ├── intent.py                ← intent.py
│   └── params.py                ← params.py
├── runtime/                 # 执行机制与接缝
│   ├── react.py                 ← react.py(有界 ReAct 内核)
│   ├── operations.py            ← operations.py(操作注册表)
│   ├── quant.py                 ← quant.py(量化任务网关)
│   ├── resume.py                ← resume.py(断点恢复协调)
│   └── state.py                 ← state.py(Send 扇出 reducer)
├── persistence/             # 存储与检查点
│   ├── database.py              ← database.py(DB 单例接缝)
│   ├── run_state.py             ← run_state.py(RunStateStore)
│   └── thread_key.py            ← thread_key.py(线程键)
└── nodes/  domains/  tools/ # 已有子包,不动
```

新子包的 `__init__.py` 只写中文 docstring,**不做 eager re-export**(吸取现有 `__init__` eager 引入 memory 导致连锁重依赖的教训)。

## 步骤

1. **前置快照**:先把当前未提交的功能改动(HITL 参数、allocation 等)提交为一个独立 commit,重构另成一个 commit,保证可审查、可回滚。
2. **移动文件**:`git mv` 按上表移动 11 个文件,创建 4 个新子包 `__init__.py`。
3. **批量更新导入**(绝对导入,机械替换,长模式优先避免误伤;`orchestrator.nodes.plan_execute`、`finance_agent.tasks.quant` 等前缀不会被误匹配):
   - 生产代码仅 2 个文件:`api/routes.py`(orchestrator.database → persistence.database,7 处)、`data/postgres_stores.py`(run_state → persistence.run_state)。`faq/repository.py`、`research/refresh.py`、`tasks/quant.py` 引用的是不动的模块,无需改。
   - 包内部:orchestrator.py(~15 处)、supervisor_graph、plan_execute(含 self 引用)、nodes/{supervisor,plan_execute,conversation}、domains/{stock,product}、run_state、memory 等约 15 个文件的相互引用。
   - 测试与评估:约 40 个测试文件 + 3 个 evals,以 sed 批量替换 + grep 核对;`from finance_agent.orchestrator import X` 裸导入形式(test_supervisor_graph_routing.py:373、test_postgres_stores.py:50 等)逐一手改。
4. **两个字符串耦合坑**:
   - `test_conversation_isolation.py:45,135` 的 monkeypatch 目标 `"finance_agent.orchestrator.database.get_database"` → 同步改为 `...persistence.database.get_database`。
   - `test_orchestrator_fanout.py` 会扫描 orchestrator.py 源码:orchestrator.py 只改 import 行,不动内容,守卫保持通过;跑该测试确认。
5. **文档同步**:更新 `README.md` 项目结构表中 orchestrator 一节、`docs/orchestration-follow-up.md` 中涉及平铺模块路径的表述。
6. **验证**:
   - `grep` 全仓确认无旧路径残留(`orchestrator.supervisor_graph`、`orchestrator.plan_execute`、`orchestrator.intent` 等 11 个模式)。
   - `python -c "import finance_agent.orchestrator; import finance_agent.orchestrator.graphs.plan_execute_graph; ..."` 冒烟导入全部新路径。
   - 全量 `python -m pytest tests/ -q`;特别关注 test_orchestrator_fanout(守卫)、test_conversation_isolation(字符串 patch)、test_supervisor_graph_routing、test_fault_tolerance_p0、test_resilience_checkpoint_and_concurrency。
7. **提交**:重构单独成 commit(如 `refactor: orchestrator 平铺模块归入 graphs/routing/runtime/persistence 子包`),与功能改动分离。

## 风险与对策

- 规模约 60 个文件、绝大多数是测试导入的机械替换,风险集中在字符串 patch 目标与裸导入形式,已逐一列入核对清单。
- `plan_execute.py` 更名为 `plan_execute_graph.py` 是唯一的改名(与 supervisor_graph/conversation_graph 命名对齐);若你想零改名,也可保留原名仅移动,实施时一行可切。
- 全量测试通过才算完成;任何红灯先修导入再收尾。
