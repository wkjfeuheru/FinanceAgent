## 目标

为 4 类业务领域（stock_research / market_insight / product_research / account_portfolio）新增「关键参数抽取 + 入参校验」模块，参数区分**必填**与**可选**（可选含用户偏好：风险偏好、投资期限）；缺必填项时用 LangGraph `interrupt()` 触发 human-in-the-loop，前端以**交互弹窗表单**呈现，用户提交后在同一会话线程 resume 继续执行。

## 已查证的关键约束

1. **只有股票、产品存在「可缺的参数」**。市场洞察 4 个采集器零入参（时间窗口读 config），账户领域只需会话里的 `customer_id`。二者在参数注册表登记为空必填集、永不弹窗（也不消费偏好）。「4 类领域都接入」体现在统一的 `REQUIRED_PARAMS`/`PARAM_SPECS` 注册表 + 统一校验节点。
2. **interrupt 必须挂在根 Supervisor 图**。`rules/CLAUDE.md` 指定依据 `rules/langgraph-guides/interrupts.md`：interrupt 需要 checkpointer，恢复时「节点从函数开头重跑」（interrupt 前的副作用须幂等）。只有根图挂了 PostgresSaver（`config.py:289`→`supervisor_graph.py:285`）；领域子图 `graph.invoke({"context": context})` 不传 config、编译时也未传 checkpointer（`orchestrator.py:204`、`domains/base.py:95`）。
3. **用户画像当前是只读摆设（必须先修的断链）**。`UserProfileCard`（`memory.py:20`）、`finance.user_profiles` 表、`get_profile`/`save_profile`（`postgres_stores.py:99/118`）、`GET /api/profile/{customer_id}`（`routes.py:422`）都齐全，但画像从未进入分析链路：`state["user_profile"]` 恒为 `{}`，`DomainTaskContext` 无 `user_profile` 字段。后果：生产路径 `profile_complete` 恒假、`personalization_status` 恒为 `research_candidate`。
4. **前端只走 SSE**。`frontend/` 是 Vue 3 + TS + Vite + Element Plus；`api/chat.ts:133` 手写 fetch+ReadableStream，事件只认 `stage`/`response`/`error`（`chat.ts:225-262`），`run_status`/`warnings` 未被消费。后端不托管前端（无 StaticFiles），开发期 Vite 代理、改源码即 HMR。
5. **参数通道复用已废弃的 `intent_slots`**：`request_parser.py:113`、`domains/stock.py:255`、`domains/product.py:135` 仍在读，旧 `SlotExtractor` 已删、当前无生产者。

## 参数模型（必填 / 可选登记处）

新增 `finance_agent/orchestrator/params.py`：

- `ParamSpec(name, label, required, kind, options, default, scope)`，`kind ∈ {text, code, choice, number}`，`scope ∈ {turn, profile}`。
- `PARAM_SPECS: dict[BusinessDomain, tuple[ParamSpec, ...]]`（唯一事实源）：
  - `STOCK_RESEARCH`：必填 `stock_target`（turn；六位代码或可唯一确定的名称，或已注册主题）；可选 `analysis_type`（choice：fundamental/technical/both）、`risk_preference`（choice，profile）、`holding_period`（choice，profile）。
  - `PRODUCT_RESEARCH`：必填 `product_reference`（turn；产品代码或名称）；可选 `risk_preference`、`holding_period`（profile）。
  - `MARKET_INSIGHT` / `ACCOUNT_PORTFOLIO`：空元组（不消费偏好，已核实工具签名）。
- `find_missing(domains, params)` 只统计 `required=True` 且 `scope="turn"` 的缺失项 → 决定是否弹窗。
- `ExtractedParams(BaseModel, extra="forbid")`：按领域分子字典 + `profile_updates`。
- `extract_params(message, history, domains, *, requester=None) -> ExtractedParams`：确定性优先（复用股票六位代码正则 `domains/stock.py:51`、theme_registry 名称匹配、产品代码/名称抽取 `domains/product.py:81-129`、mode 关键词）；仅有必填项缺失时才调一次 JSON-mode LLM（镜像 `DeepSeekIntentClassifier` 的 requester 注入以便测试），模型用 `config.get_intent_model()`、温度复用孤儿配置 `AGENT_TEMPERATURES["slot_extraction"]`（`config.py:223`）；任何失败只降级不抛出。
- 偏好取值校验复用既有映射：`memory.py:337-343` 的 R1–R5 别名、`product_research/rules.py:43-68` 的 `normalize_horizon`。非法值降级为 warning，不阻塞。
- `build_question(missing, optional_specs)` 生成确定性中文追问文案。

## 根图新增 `extract` + `validate` 节点

`supervisor_graph.py` / `nodes/supervisor.py`：

- `SupervisorState` 增 `extracted_params`、`user_profile`、`param_cancelled`、`param_missing`（回传前端）。
- `make_classify_node` 的**入口复位字典加入 `extracted_params: {}` / `param_cancelled: False`**，维持既有「每轮从干净状态开始」不变量（`nodes/supervisor.py:37`）。
- 边改为 `START → classify → extract → validate → route → {conversation, clarify, single_domain, plan}`。
- **拆两节点是硬要求**：恢复时只重跑 `validate`，含 LLM 调用的 `extract` 产物已在 checkpoint，不重复付费。节点内**不得**用 try/except 包住 `interrupt`（规范硬性要求）。
- `extract`：`conversation`/`clarify` 模式直接短路返回 `{}`。
- `validate`：算 `missing`；为空 → 返回 `{}`。非空且图有 checkpointer → `answer = interrupt({"missing":..., "question":..., "fields":[表单规格]})`；拿回后 `merge_answer` 再校验一次：仍缺则退化为现有 clarify 式收尾（`run_status="partial"`）；若 answer 为取消标记则收尾为 `completed` 并置 `param_cancelled`。**不重问**（单次询问，前端已做必填校验）。
- 是否启用 interrupt 由 `build_supervisor_graph(checkpointer=...)` 决定：`checkpointer is None` 时降级为澄清式（测试与单次调用行为同现状）。新增 `SupervisorDependencies.max_param_asks: int = 0`（预留，便于后续开启重问）。

## 恢复路径、取消与响应投影

- `AdvisorSystem.handle_message` 增 `resume: bool = False, answers: dict[str, Any] | None = None`；`handle_message_stream` 同步透传。
- 恢复逻辑 `_resume_or_restart`：`root.get_state(config)` 探测 pending（`snapshot.next` 非空且 `snapshot.tasks[].interrupts` 非空）。命中且 `resume=True` → `root.invoke(Command(resume=answers), config)`。命中但本轮是**自由文本新消息**（`resume=False` 或 answers 为空）→ 先 `root.invoke(Command(resume={"__cancel__": True}), config)` 关掉挂起 run，再 `root.invoke(新输入, config)` 开新轮。`get_state` 不可用/无 checkpointer/异常 → 一律回退普通轮次。
- 偏好落库：answers 里的 `risk_preference`/`holding_period` 经校验归一后 `memory.save_profile` 写入长期画像（`memory.py:309`），同时注入本轮。
- 新增 `project_interrupt_state(result, conversation_id)`：`result["__interrupt__"]` 存在时输出 `final_response=question`、`run_status="awaiting_input"`、`interrupt_id`、`pending_input={fields, missing, question}`、`warnings=["awaiting_user_input"]`，并跳过 `_persist_pending_outcomes`（`orchestrator.py:558`）。追问文本仍按普通助手消息落库，历史连贯。
- `RunStatus` 增 `AWAITING_INPUT = "awaiting_input"`（已有 `RUNNING` 非终态先例，`contracts/schema/enums.py:14`）。
- 合规口径：追问为服务端确定性模板、仅含表单字段与提示、不含分析结论，且挂在合规出口之前的图内 interrupt。按既有先例（middleware `BLOCKED_RESPONSE` 在 `orchestrator.py:469` 提前返回、不过合规）登记为**豁免项并写入文档**。

## 默认决策（可在批准时推翻）

1. 弹窗仅在缺必填项时出现，偏好作为可选字段同框收集。
2. 弹窗填写的偏好写入长期画像并本轮生效。
3. 挂起期间用户发自由文本新消息 → 放弃挂起 run 并开新轮。
4. 偏好全链路生效（含修复画像注入断链）。
5. 单次询问，不自动重问；追问模板豁免合规出口。
